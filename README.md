# Rio - Raw Information Orchestrator

Rio helps an assistant set up a local, evidence-backed second brain without asking a
language model to invent the folder structure, templates, or setup checklist.

**The assistant handles the conversation. Scripts handle the predictable files.**

After you confirm your purpose, destination, source boundaries, and permissions, Rio
creates exactly **17 directories and 20 files**, validates them, and stops after the
structural bootstrap. The generated checklist guides the remaining work; its existence
does not mean ingestion, recovery, or automation already works.

## Start with an assistant

Clone or download this repository, then give your assistant this instruction:

> Read `skills/rio-setup/SKILL.md` from the Rio checkout and follow it to set up a
> new second brain. Ask me for the missing setup decisions one at a time. Use the
> packaged scripts and templates; do not create the files from memory. Stop after
> bootstrap and show me the validation result and remaining checklist.

Choose an **empty destination outside the Rio checkout**. A nonempty root, including
one containing only hidden files, is refused rather than cleaned or migrated.

The setup conversation covers your primary use case, sources and their purpose,
accounts or local locations, in/out scope, dates and volume limits, access methods,
local retention, and action boundaries. A source may be a supplied file, export,
built-in connector, or MCP; Rio does not prescribe or install a vendor's tools.
Source capability checks are a later checklist step, not a claim made by bootstrap.

The [skill](skills/rio-setup/SKILL.md) is optional: ordinary chat and local script
execution work too. Keep the whole repository together; the skill's relative
references are not a standalone plugin installation.

## Run the scripts directly

Python **3.11 or newer**, using only the standard library. The executable may be
named `python` or `python3`.

1. Copy [the fictional sample](fixtures/sample-answers.json) to a file **outside**
   the destination root.
2. Fill it using your actual choices and the [answer format](references/answers-format.md).
   Set the exact destination. Keep `confirmed` false until you approve the record.
3. Set `confirmed` true only after approval, then run:

```sh
python scripts/bootstrap.py --answers "../confirmed-answers.json" --root "../my-second-brain"
python scripts/validate.py --root "../my-second-brain" --check-reference
```

Use the same commands with `python3` when that is the installed launcher. Quoted arguments
support spaces and non-ASCII names; the scripts use native filesystem path semantics.
From another working directory, pass the full path to each script. Relative
`workspace.destination` values resolve beside the answers file; `--root` resolves from
your shell's current directory. Both must identify the same destination.

The source locations in answers are recorded, **not read or fetched**. Bootstrap never
connects accounts, ingests source content, sends messages, edits boards, or schedules jobs.

## What you get

```text
AGENTS.md                 Short assistant startup instructions
README.md                 Human entry point and limitations
index.md                  Active work
log.md                    Operation history
raw/                      Immutable evidence channels, initially empty
00-Inbox/                 Unresolved material
10-Notes/                 Entities and concepts
20-Projects/              Finite outcomes
30-Areas/                 Ongoing responsibilities
40-Resources/             Reference material
50-Archive/               Archived knowledge
_meta/                    Scope, conventions, answers, setup checklist,
                          source/processing records, navigation, seven
                          templates, and assistant stance/memory files
```

The [canonical checklist](references/setup-checklist.md) separates required acceptance
criteria from observed evidence. Only S01-S03 are completed by this bootstrap, after
confirmed answers and successful structural checks. Later work remains unexecuted.

## Validation and tests

```sh
python -m unittest discover -s tests -v
python tests/harness.py
python scripts/render_reference.py --check
```

The harness uses fictional answers and disposable temporary directories, including
paths with spaces. To evaluate a starter generated by another assistant, run the
read-only validator against it. See the [manual runner protocol](references/operating-contract.md).
No app-specific session orchestration is required.

Tests cover nonempty and hidden roots, unsafe paths, source plans, template schemas,
checklist dependencies, duplicate runs, and interrupted finalization. The bundled
[CI workflow](.github/workflows/tests.yml) targets Windows, Linux, and macOS. The initial
local trial ran on Windows; check CI results for actual execution on other systems.

### Command results

`bootstrap.py` exits 0 on success, 2 for command-line usage errors, 3 for rejected input or
unsafe/precondition failures, and 4 if post-write validation finds a defect. `validate.py`
exits 0 when valid, 1 for reported defects, 2 for usage errors, and 3 for invalid package
configuration. Add `--json` for machine-readable stdout. Validation writes nothing into the
evaluated root.

JSON `created_count` counts paths created in this invocation: 37 for the scaffold,
or 38 if the root itself also had to be created. `next_step: "S04"` means
dependency-eligible, not executed or automatically authorized.

## Package layout

- `assets/vault/`: fixed starter-file assets.
- `manifests/scaffold.json`: authoritative 17-directory/20-file inventory.
- `manifests/tasks.json`: authoritative S01-S16 definitions and dependencies.
- `references/`: setup, source-selection, and operating contracts.
- `scripts/bootstrap.py`: parse-confirm-first, exclusive-create bootstrap.
- `scripts/validate.py`: read-only bootstrap-state validator.
- `fixtures/` and `tests/`: fictional portable integration inputs and harness.
- `skills/rio-setup/SKILL.md`: explicit user-invoked, initial-only entry point.

Keep or install the whole package tree together. The skill uses relative paths to the
package's manifests, references, fixtures, assets, and scripts; the skill directory alone
is intentionally not an installable unit, and this kit does not claim integration with a
particular plugin installer.

## Safety and limits

All answers and manifests are parsed before filesystem effects. Unknown fields, unsupported
enum values, control characters, path traversal, absolute manifest destinations, conflicting
authorization, nonempty roots (including hidden entries), files, and detectable links or
reparse points are rejected. A missing root is created only when explicitly authorized and
its immediate real-directory parent exists. Files use exclusive no-overwrite creation.

There is no atomic whole-tree transaction. Concurrent processes can race between checks and
writes; exclusive creates prevent overwriting, and failures report the exact created-path
prefix while preserving all bytes. The kit never recursively rolls back a user root.
Reparse-point detection is implemented with portable link checks plus Windows file
attributes, but only the current operating system is exercised by a given test run.
Platform-specific tests report skips where a capability cannot be exercised.

The frontmatter parser intentionally supports only the generated canonical subset: one
`key: value` per line with JSON-compatible strings, arrays, and `null`. Unsupported YAML is
rejected rather than guessed. Bootstrap-only validation is intentionally strict and is not
a validator for an evolved/mature vault. It verifies structure and internally generated
evidence records; it cannot independently prove the truth of a human confirmation merely
because text is present. Ingestion, source capability verification,
recovery tests, querying, and automation are deferred checklist work, not hidden features.

## Inspiration and acknowledgments

Rio builds on established ideas rather than claiming to have invented personal knowledge
management. These public resources deserve credit and are useful reading in their own right:

- **Tiago Forte's [PARA method](https://fortelabs.com/blog/para/)** is the direct
  organizational inspiration for Projects, Areas, Resources, and Archives.
  Rio adds an inbox, reusable notes, evidence storage, and operational records around
  that familiar structure.
- **Tiago Forte's [Building a Second Brain](https://www.buildingasecondbrain.com/)**
  provides the broader motivation: turn captured information into useful, actionable
  knowledge rather than collecting it for its own sake. Rio is an independent
  implementation, not an official version of that system.
- **The [AGENTS.md convention](https://agents.md/)** provides the public convention
  for a predictable assistant instruction entry point. Rio generates a short file
  that points to the user's actual scope, conventions, and checklist.
- **The [Agent Skills format](https://agentskills.io/home)** informs the optional
  skill entry point and its use of supporting references and scripts. Individual
  clients differ; Rio's plain-file and command-line path remains available.

These are acknowledgments of ideas and interoperability conventions, not claims of
affiliation, endorsement, or ownership of those works. Their names and materials retain
their respective ownership and terms. Rio does not bundle their books or course content.
